2. ARCHITECTURAL VULNERABILITIES & PRODUCTION CODE FIXES (V12.4.3.7.16)
------------------------------------------------------------------------------------------
[WORKSTREAM A] SerpApi Demand Collector & Attestation Invariants
- Vulnerability / Risk:
  In-memory ephemeral proofs could grant live origin claims without confirming that a durable HMAC-SHA256
  attestation was successfully committed and verified on disk. If attestation writing crashed or was delayed,
  in-memory state could allow unverified or forged proofs to elevate evidence eligibility.
- Production Code Fix:
  1) Mandatory Durable Attestation Verification on Disk:
     `persistCollectorReceiptAtomically` strictly enforces that a valid `diskAttestation` (`ProviderTransportAttestationV1`)
     exists on disk and passes cryptographic signature verification before setting `originVerified = true` or granting
     authoritative live origin.
  2) In-Memory Mutation Fence:
     If an in-memory attestation object is provided, its signature and `captureMethod` must strictly match the disk
     attestation. Any divergent in-memory attestation (e.g. `captureMethod: "SIMULATED"`) is immediately demoted
     to simulated proof without live authority.
  3) Readback Verification & Tamper Eviction:
     In `resolveVerifiedDemandEvidence` and canonical descriptors, attestation is re-verified from disk readback.
     If an attestation is deleted or tampered with on disk, the in-memory cache is evicted and evidence resolves
     fail-closed as `ORIGIN_UNVERIFIED` / `INSUFFICIENT_EVIDENCE`.
  4) Exact Scope Binding:
     `requestFingerprint` and attestation parameters bind exact `workspaceId`, `productId`, and `researchRunId`.

[WORKSTREAM B] Transactional All-or-Nothing Database Import (CSV & Pre-Parsed Rows)
- Vulnerability / Risk:
  Sequential database inserts could partially succeed when importing Google Trends demand series, leaving orphaned
  or corrupted partial records. Errors were previously swallowed into `skippedCount++`, masking failures.
- Production Code Fix:
  1) Shared Atomic Import Service (`executeDemandObservationBatchImport`):
     Created unified service used by both `POST /api/v1/demand/import` and `importGoogleTrendsCsvToDatabase`.
  2) All-or-Nothing `$transaction` Persistence:
     All rows in a batch are committed inside `prisma.$transaction`. If any row fails validation, encounters a
     database constraint violation, or creates an unresolvable duplicate with conflicting values, the ENTIRE batch
     rolls back: 0 new rows written to database.
  3) Concurrency & Duplicate Handling:
     Intra-batch and database duplicate checks: identical duplicates are safely deduplicated (skipped); conflicting
     demand values for the same timestamp trigger immediate `409 CONFLICTING_DUPLICATE_OBSERVATION` rollback.
  4) Tenant and Product Boundary Enforcement:
     Enforces tenant isolation via `buildAuthorizedProductWhere` and validates that `productId` exists before import.
     Rejects non-existent products with `404 PRODUCT_NOT_FOUND` and unauthorized tenants with `403 FORBIDDEN_WORKSPACE_PRODUCT`.
  5) Strict 64-Hex SHA-256 Provenance Check:
     Rejects fake or truncated hashes; requires authentic 64-character hex checksums for official CSV provenance.

[WORKSTREAM C] Real Google Ads Merchant PDP Destination Verification
- Vulnerability / Risk:
  Pure URL syntax matching was conflated with true merchant product page verification, allowing landing pages or
  brand homepages without verified product content to be marked as exact product matches.
- Production Code Fix:
  1) URL Syntax Pre-Screen Isolation:
     `classifyVerifiedGoogleMerchantDestination` performs pure URL structure validation, returning
     `urlStructureValid: true`, `destinationVerificationStatus: "PDP_URL_STRUCTURE_VALID"`, and `isVerifiedPdp: false`.
  2) Live Merchant PDP Resolver (`verifyLiveMerchantProductPageDestination`):
     Performs actual live destination verification with:
     - SSRF preflight protection: rejects loopback (127.0.0.1, localhost), private IP ranges (10.*, 172.16-31.*, 192.168.*),
       and cloud metadata endpoints (169.254.169.254).
     - Bounded redirect traversal (maximum 5 hops).
     - HTTP response status 2xx check and strict response size cap (2 MB limit).
     - 10-second bounded timeout with `AbortSignal`.
     - Store domain match and product handle path alignment.
     - Body inspection for product schema markup (JSON-LD `Product`, OpenGraph `og:type` product, or product title match).
  3) Simulation Fence:
     When invoked with a test injection `fetchFn`, destination verification marks `isLiveExternalProof: false`
     and `verificationMode: "TEST_VERIFIED_ONLY"`. Live G16 elevation is strictly prohibited without genuine live HTTP proof.
  4) Orchestrator Integration:
     `runEvergreenProductResearch` strictly gates `EXACT_PRODUCT_MATCH` on `isVerifiedPdp && isLiveExternalProof`.
     Historical UAHPET 9 Google creatives preserved: exact=0, brand=8, unrelated=1.
