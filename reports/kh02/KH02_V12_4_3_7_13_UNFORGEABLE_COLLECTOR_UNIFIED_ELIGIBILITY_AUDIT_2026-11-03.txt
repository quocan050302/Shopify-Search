2. ROOT CAUSE & CODE FIXES FOR ALL VULNERABILITIES & INVARIANTS
------------------------------------------------------------------------------------------
[P0-A] Unforgeable Collector Origin Minting
- File & Lines: src/services/kh02/demand/temporalDemandEngine.ts:365-475, 1420-1490, 1850-2050
- Root Cause:
  Previously, callers could synthesize or pass `originKind: "ACTUAL_PROVIDER_INVOCATION"` directly into
  `persistCollectorReceiptAtomically()`, or invoke `recordTrustedProviderInvocation()` with simulated
  payloads and gain unverified live origin credit.
- Code Fix:
  1) Introduced private `TrustedInvocationProof` minting mechanism that is strictly bound to
     `(attemptId, receiptId, rawResponseSha256, provider, targetProductOrKeyword, region)`.
  2) Real `executeTrustedSerpApiDemandRequest()` only mints proof when executing real native network transport
     against official endpoint `https://serpapi.com/search.json` with HTTP 200, valid search_metadata.id,
     and redirect: "error".
  3) Calls to `persistCollectorReceiptAtomically()` lacking a valid proof have `originKind` demoted to
     `LOCAL_INTEGRITY_ONLY`, `originVerified` set to `false`, and are evicted from in-memory trusted registries.
  4) Controlled tests use `registerTestControlledInvocationProof()` in isolated test harnesses to verify
     positive readback paths without polluting production state.

[P0-B] Mandatory Database Lock in Atomic Receipt Persistence
- File & Lines: src/services/kh02/demand/temporalDemandEngine.ts:1550-1580
- Root Cause:
  Stage 3 of `persistCollectorReceiptAtomically()` previously treated database lock acquisition as optional
  or logged a warning if `acquireDurableLedgerLockAsync(dbLockPath)` failed, risking concurrent uncoordinated
  Prisma writes and race conditions during database schema updates.
- Code Fix:
  Enforced mandatory DB lock acquisition. If `dbLockRes.acquired === false`, `persistCollectorReceiptAtomically()`
  aborts immediately with `state: "LOCK_TIMEOUT"`, `errorCode: "DB_LOCK_TIMEOUT"`, `eligible: false`, and
  `dbCommitted: false`, performing exactly 0 Prisma database writes and leaving the ledger staged as
  `LEDGER_PENDING_DB` (fail closed).

[P0-C] Unified Receipt Verification & Decision Proof Issuance
- File & Lines: src/services/kh02/demand/temporalDemandEngine.ts:2580-2645, 2980-3050
- Root Cause:
  Downstream components historically implemented fragmented eligibility checks, sometimes trusting the ledger
  file alone, sometimes trusting the SQLite table alone, and omitting verifiable decision proofs.
- Code Fix:
  1) Canonicalized `verifyReceiptEligibility = resolveVerifiedDemandEvidence`.
  2) On successful dual-store verification (both ledger `commitState === "EVIDENCE_ELIGIBLE"` and SQLite
     `ResearchEvidence` matching SHA-256 and byte counts), mints an immutable `VerifiedEligibilityProof`
     recorded in `verifiedDecisionProofs`.
  3) When `strictLiveOrigin === true`, strictly requires receipt presence in `trustedInvocationsRegistry`.

[P1-E] Lock Reclaim Inode Verification
- File & Lines: src/services/kh02/demand/temporalDemandEngine.ts:980-1035
- Root Cause:
  During dead lock reclamation, renaming an expired lock file to a claim path could race with another process
  re-creating or replacing the lock file.
- Code Fix:
  1) Verifies `statBefore.ino === statAfter.ino` and `statBefore.dev === statAfter.dev` across the rename.
  2) Verifies `reclaimedLock.ownerId === expectedOwnerId` after atomic rename.
  3) If an inode or owner replacement race is detected, safely restores the file and aborts with `LOCK_TIMEOUT`.

[P1-F] Native Fetch Check & Target Host Validation
- File & Lines: src/services/kh02/demand/temporalDemandEngine.ts:1820-1875
- Root Cause:
  Global fetch could be monkeypatched or redirected to unverified localhost / proxy endpoints without detection.
- Code Fix:
  1) Evaluates `Function.prototype.toString.call(fetch).includes("[native code]")` to verify un-monkeypatched fetch.
  2) Strictly validates `urlObj.protocol === "https:"` and `(urlObj.port === "" || urlObj.port === "443")`.
  3) Strictly validates target hostname against official allowlist (`serpapi.com`), rejecting non-conforming
     targets fail-closed with `ORIGIN_UNVERIFIED`.

3. RECEIPT COMMIT STATE MACHINE & CROSS-STORE COORDINATION
------------------------------------------------------------------------------------------
State Transitions:
  NEW_ATTEMPT
    -> TRANSPORT_RESPONSE_200 (HTTP 200 + native fetch + serpapi.com + search_metadata.id)
    -> RAW_ARTIFACT_VERIFIED (64-hex SHA-256 content-addressed JSON artifact on disk)
    -> PROOF_MINTED (Private module TrustedInvocationProof minted for attempt+receipt+SHA)
    -> LEDGER_PENDING_DB (Staged under .lock via temp+fsync+rename; eligible=false)
    -> DB_LOCK_ACQUIRED (Mandatory .db.lock acquisition; fails to LOCK_TIMEOUT if busy)
    -> DB_COMMITTED (Prisma ResearchEvidence upsert awaited)
    -> DB_READBACK_VERIFIED (Prisma findUnique verified for id, sourceContentRef, observedValue)
    -> EVIDENCE_ELIGIBLE (CAS transition under .lock; eligible=true, dbCommitted=true, verifiedAt!=null)
    -> DECISION_PROOF_MINTED (VerifiedEligibilityProof issued upon canonical verification)
