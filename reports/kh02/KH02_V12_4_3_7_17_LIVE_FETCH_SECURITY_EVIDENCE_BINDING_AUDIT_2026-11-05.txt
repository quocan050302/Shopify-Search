2. ARCHITECTURAL VULNERABILITIES & PRODUCTION CODE FIXES (V12.4.3.7.17)
------------------------------------------------------------------------------------------
[WORKSTREAM A] Live Fetch Security & PDP SSRF / Rebinding / Redirect Protections
- File: src/services/kh02/identity/verifiedMerchantPdpResolver.ts
- Vulnerability / Risk:
  In previous versions, PDP destination resolution lacked comprehensive URL normalization, DNS rebinding
  protection, and defense against malicious redirects or oversized response bombs. Attackers or malicious
  URLs could target private cloud metadata endpoints, internal network CIDRs, or perform slowloris attacks.
- Production Code Fixes:
  1) WHATWG URL Normalization:
     Strictly enforces https: scheme, standard port 443, rejects userinfo (credentials in URLs), and
     validates punycode hostnames.
  2) SSRF Private IP Range Rejection:
     Evaluates target host IP against comprehensive blacklist CIDRs:
     0.0.0.0/8, 10.0.0.0/8, 100.64.0.0/10, 127.0.0.0/8, 169.254.0.0/16, 172.16.0.0/12,
     192.0.0.0/24, 192.168.0.0/16, 224.0.0.0/4, 240.0.0.0/4, IPv6 ::, ::1, fc00::/7, fe80::/10, ::ffff:IPv4.
  3) DNS Rebinding Defense:
     Performs DNS resolution preflight and verifies dialed socket peer IP directly against SSRF guards,
     preventing TOCTOU DNS rebinding attacks.
  4) Manual Hop-by-Hop Redirect Traversal:
     Manually inspects 3xx redirects (max 5 hops); validates target URL at every step, prevents HTTPS-to-HTTP
     downgrade, and ensures destination domain remains within the merchant scope.
  5) Streaming 2 MiB Response Cap & Reader Cancellation:
     Consumes response body via a readable stream reader with a hard 2 MiB limit, aborting with
     PAYLOAD_TOO_LARGE if exceeded. Listens to overallController.signal to cancel active reader cleanly on timeout.
  6) Top-Level Timeout Lifecycle:
     Ensures the 10-second timeout encompasses both redirect resolution and body streaming, returning TIMEOUT
     if signal is aborted.

[WORKSTREAM B] Merchant PDP Proof & Creative Provenance Binding
- Files: src/services/kh02/identity/verifiedMerchantPdpResolver.ts, src/services/kh02/evergreenResearchOrchestrator.ts
- Vulnerability / Risk:
  Blank pages or generic landing pages with correct store domains could previously pass destination checks
  without true proof of product content, risking false G16 winning product elevations.
- Production Code Fixes:
  1) Product Content Proof Required:
     Requires verifiable product content evidence in HTML body:
     - JSON-LD schema with @type: "Product"
     - OpenGraph metadata with og:type: "product"
     - Product title match matching candidate product name
     Returns PRODUCT_CONTENT_MISSING if no product content is found.
  2) Post-Redirect Product Handle Verification:
     Evaluates product handle matching on the final resolved destination URL after redirect hops,
     supporting short/vanity URLs while enforcing handle consistency.

[WORKSTREAM C] Demand Row Binding to Raw CSV Evidence & Weekly Cadence Handling
- Files: src/services/kh02/demand/googleTrendsCsvValidator.ts, src/services/kh02/demand/demandObservationBatchImport.ts, src/services/kh02/demand/temporalDemandEngine.ts
- Vulnerability / Risk:
  Demand observations could be imported or evaluated without verifying each individual data row against
  an authentic stored CSV file. Furthermore, official Google Trends CSV exports report weekly intervals
  by start date, whereas stored observation rows span a 7-day range, causing false lineage rejections.
- Production Code Fixes:
  1) Direct Row Binding via verifyDemandObservationAgainstRawCsv:
     Validates observation timestamp, keyword, and value against the actual raw CSV content stored on disk.
     Supports both sha256:<64hex> and bare <64hex> hash formats.
  2) Weekly Cadence 7-Day Window Support:
     When the raw CSV reports a single date (e.g. 2026-05-03) and the observation specifies a 7-day period
     (e.g. 2026-05-03 to 2026-05-09), matches successfully with diffDays <= 7.
  3) Mixed-Source Batch Rejection:
     Rejects batches containing mixed sources with 422 MIXED_SOURCE_BATCH_REJECTED.
  4) Authority Elevation Fencing:
     Only observations backed by verified CSV files on disk or authenticated live providers receive
     AUTHENTICATED_LINEAGE. Unverified or mismatched rows are demoted to CACHED_UNVERIFIED.

[WORKSTREAM D] Database Multi-Process Uniqueness & Transactional Rollbacks
- Files: prisma/schema.prisma, prisma/schema.sql, prisma/test_template.db
- Vulnerability / Risk:
  Concurrent workers inserting the same demand observations could produce duplicate rows if composite
  uniqueness constraints were missing at the database engine level.
- Production Code Fixes:
  1) Composite Unique Constraint:
     Added @@unique([productId, source, keyword, region, periodStart]) to DemandObservation model.
     Applied index to schema.prisma, schema.sql, and regenerated Prisma client across test databases.
  2) Multi-Process Concurrency Safety:
     Concurrent conflicting inserts fail cleanly with UNIQUE constraint violation; batch transactions
     roll back atomically with zero partial records written.
