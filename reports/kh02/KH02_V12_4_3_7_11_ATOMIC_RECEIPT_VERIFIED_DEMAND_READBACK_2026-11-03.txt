3. RECEIPT STATE MACHINE & ATOMICITY GUARANTEE BOUNDARIES
- Explicit State Machine:
  NEW_ATTEMPT -> RESPONSE_RECEIVED -> RAW_CONTENT_VERIFIED -> LEDGER_DURABLE -> DB_COMMITTED -> DB_READBACK_VERIFIED -> EVIDENCE_ELIGIBLE
  Fault states: LOCK_TIMEOUT, HASH_MISMATCH, RECEIPT_CONFLICT, LEDGER_WRITE_FAILED, DB_WRITE_FAILED, DB_READBACK_FAILED, RECOVERY_REQUIRED.
- Honest Distributed Atomicity Notice:
  Filesystem and SQLite DB do not share a single distributed 2PC transaction. Staged commit ensures:
  1) Raw payload bytes written immutably first (content-addressed SHA-256).
  2) Ledger file written atomically via tmp file + rename + readback under lock.
  3) Database record upserted and read back with identical SHA-256.
  If DB write fails after ledger write, status is FAILED (DB_WRITE_FAILED), never VERIFIED_COMMITTED. Crash recovery reconciles idempotently from durable ledger.
