[02] P0-CRITICAL & P0-HIGH DEFECT ROOT CAUSE AND CODE REMEDIATION
--------------------------------------------------------------------------------
1. P0-CRITICAL: Dangerous Shared Directory File Cleanup in Unit Tests
   - Offending File: tests/unit/kh02/v12_4_3_PostReviewHardening_2026_11_03.test.ts
   - Root Cause: afterAll hook iterated data/provider_receipts and deleted files not in
     a hardcoded fixture list, risking deletion of authentic evidence and race conditions.
   - Remediation:
     * Added setProviderReceiptStorageDirForTest(dir) and getProviderReceiptStorageDir()
       in src/services/kh02/demand/temporalDemandEngine.ts.
     * Rewrote test setup in PostReviewHardening to create an isolated temporary directory
       under os.tmpdir() with run-owner marker file (.kh02_run_owner).
     * afterAll exclusively cleans up the owned temporary test directory.
     * Verified data/provider_receipts/ 4 baseline files remain untouched byte-for-byte.

2. P0-HIGH: Collector-Only Trusted Origin & Capability Token
   - File: src/services/kh02/demand/temporalDemandEngine.ts
   - Root Cause: Callers could record originKind="ACTUAL_PROVIDER_INVOCATION" directly without
     an active collector transport session or capability token.
   - Remediation:
     * Introduced createCollectorCapabilityToken() and isValidCollectorCapabilityToken().
     * Enforced two-stage collector invocation lifecycle:
       recordProviderInvocationAttempt() -> finalizeProviderInvocationFromTransport().
     * recordTrustedProviderInvocation() rejects originKind="ACTUAL_PROVIDER_INVOCATION"
       if called without a verified CollectorCapabilityToken.
     * Descriptors lacking originKind strictly default to LOCAL_INTEGRITY_ONLY.

3. P0-HIGH: Durable Receipt Persistence & Ledger
   - File: src/services/kh02/demand/temporalDemandEngine.ts
   - Root Cause: In-memory Maps (trustedInvocationLedger) were lost across worker restarts.
   - Remediation:
     * Implemented disk-based durable ledger (.provider_receipt_ledger.json) in active storage dir.
     * Integrated fallback lookup: getTrustedProviderReceipt() and findTrustedReceiptByHash()
       read from durable disk ledger on in-memory cache miss.
     * Durable ledger survives in-memory cache clears across separate worker lifecycles.

4. P0-HIGH: Test Fixture Fail-Closed Classification
   - Files: src/services/kh02/demand/temporalDemandEngine.ts, tests/setupTestEnvironment.ts
   - Root Cause: Synthetic unit test fixture receipts could produce AUTHORITATIVE_VERIFIED.
   - Remediation:
     * initKnownUnitFixtures() removed from module evaluation; isolated to explicit test setup.
     * KNOWN_UNIT_FIXTURE_SHAS explicitly assigned originKind="UNIT_FIXTURE".
     * Fixture receipts fail closed: providerOriginVerified=false, sourceAuthority="FIXTURE_ONLY".
     * Business gates G15 and G16 strictly reject FIXTURE_ONLY from Evergreen acceptance.

5. P1: Strict Backtest Chronology & Cadence Protection
   - File: src/services/kh02/demand/temporalDemandEngine.ts
   - Root Cause: 24h grace window permitted future points to leak into asOf historical replays.
   - Remediation:
     * When strictChronological === true, maxAllowedTimestamp = Date.now() (no 24h grace).
     * Observations lacking verified knownAt/ingestedAt timestamps are rejected.
     * Cadence protection: empirical weekly intervals (medianDelta <= 14) tagged as MONTHLY
       are normalized to WEEKLY, preventing false sampling density passes.

[04] EVIDENCE TRUST TIER AUDIT
--------------------------------------------------------------------------------
- FIXTURE / FIXTURE_ONLY: Assigned to test fixtures in tests/fixtures/.
  Cannot produce AUTHORITATIVE_VERIFIED or pass G15/G16 business gates.
- LOCAL_INTEGRITY_ONLY: Stored CSV or local payload with valid 64-hex checksum.
  Proves file content integrity, NOT live network invocation origin.
- AUTHORITATIVE_VERIFIED / LIVE_ORIGIN_VERIFIED: Strictly reserved for verified
  collector transport invocations with durable ledger record and deep content match.
- INSUFFICIENT_HISTORICAL_EVIDENCE: Truthfully assigned when external live sources
  are unauthenticated, span < 60 days, or coverage ratio < 40%.
