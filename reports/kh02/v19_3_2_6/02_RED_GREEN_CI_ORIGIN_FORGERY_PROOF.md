# SWAI KH-02 — V12.4.3.7.19.3.2.6
## Red-to-Green CI Origin Forgery Proof & Regression Verification

### 1. Executive Summary

This audit proves the complete closure of the CI Origin Registration vulnerability identified in KH-02 V19.3.2.5. Prior to this patch, an external module, attacker, or unit test could invoke exported registration methods or spoof capability tokens to register arbitrary GitHub workflow run IDs as authentic, bypassing release gating without any verifiable execution on GitHub Actions servers.

---

### 2. RED State: Vulnerability Demonstration

In V19.3.2.5:
1. `registerVerifiedRemoteCiRun(runId, evidence)` was directly exported from `src/services/kh02/release/githubActionsCiEvidence.ts`. Any caller could invoke:
   ```typescript
   registerVerifiedRemoteCiRun(9999999999, {
     runId: 9999999999,
     headSha: testedCodeSha,
     conclusion: "success",
     status: "completed",
     repository: "quocan050302/Shopify-Search",
     branch: "feature/kh02-walmart-us-jina-reader-v12.4.3.5.1",
     workflowPath: ".github/workflows/kh02-ci.yml",
     isUnitTestMock: false, // Forged claim of genuine remote run
     source: "GITHUB_API"
   });
   ```
2. The registration would succeed, placing an unverified run into the provider registry.
3. Subsequent calls to `mintCiAttestationToken` would observe the entry in the registry and issue an authentic HMAC token (`swai_ci_v19_3_2_4_*`).
4. The release evidence evaluator would evaluate `ciStatus: "CI_PASS"`, producing an illegitimate release pass.

---

### 3. GREEN State: Enforced Defenses in V19.3.2.6

In V19.3.2.6, three independent defense-in-depth mechanisms prevent this attack:

1. **Unexported Registration Primitive**:
   - `_registerVerifiedRemoteCiRun` is completely private and unexported.
   - It is only invoked within `verifyRemoteGitHubActionsRun` when a genuine HTTPS response from `api.github.com` has been parsed and verified.

2. **Forced Mock Quarantine on Test Helpers**:
   - The only exported registration function for testing is `_testOnlyRegisterVerifiedRemoteCiRun`.
   - Its implementation unconditionally overrides the `isUnitTestMock` field:
     ```typescript
     export function _testOnlyRegisterVerifiedRemoteCiRun(runId: number, evidence: GitHubWorkflowRunEvidence): void {
       _registerVerifiedRemoteCiRun(runId, {
         ...evidence,
         isUnitTestMock: true // Enforced: Cannot be overridden to false
       });
     }
     ```
   - Attempting to pass `isUnitTestMock: false` is discarded.

3. **Release Evaluator Strict Quarantine**:
   - In `validateVerifiedCiAttestation` and `evaluateReleaseEvidence`, any proof containing `isUnitTestMock: true` is immediately rejected for release:
     ```typescript
     if (entry.isUnitTestMock) {
       return {
         valid: false,
         reason: "RELEASE_EVALUATOR_REJECTED_MOCK_CI: Proof was generated by a unit test mock helper and cannot satisfy release gate."
       };
     }
     ```

---

### 4. Verification Evidence (T01–T07 Adversarial Tests)

- **T01**: Passing a forged payload to `mintCiAttestationToken` without prior authentic registration yields an untrusted token (`swai_ci_untrusted_*`).
- **T02**: `registerVerifiedRemoteCiRun` is absent from module exports; calling `_testOnlyRegisterVerifiedRemoteCiRun` forces `isUnitTestMock: true`.
- **T03**: Signed forged HMAC payload fails verifier, validator, and release evaluator.
- **T04**: CustomFetch mock is quarantined with `isUnitTestMock: true`.
- **T05**: Spoofing `isUnitTestMock: false` or setting `NODE_ENV=production` fails to bypass the quarantine.
- **T06**: Test fixture runs registered via test helpers cannot satisfy release gates.
- **T07**: Wrong workflow path, branch, SHA, repo, event, conclusion, or status fails closed.
