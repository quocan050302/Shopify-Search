2. ARCHITECTURAL VULNERABILITIES & PRODUCTION CODE FIXES (V12.4.3.7.18)

[WORKSTREAM A] Actual Socket Trust, IP Pinning & Audited TLS Connection
- File: src/services/kh02/identity/verifiedMerchantPdpResolver.ts
- Vulnerabilities / Risks:
  Previous mock-based fetch simulations checked simulated peer IPs without proving that actual
  TCP sockets were pinned to approved addresses, leaving room for DNS rebinding TOCTOU races
  where DNS changes between preflight validation and socket connection. Furthermore, mock fetches
  returning tlsVerified: true risked masquerading as live external proofs.
- Production Code Fixes:
  1) Pinned IP Socket Dialing (performAuditedSecureTlsFetch):
     Pre-resolves host IP with WHATWG SSRF CIDR checks (including IPv4-mapped IPv6 ::ffff:),
     then dials strictly the validated IP address while preserving domain SNI for valid TLS
     handshake without certificate name mismatch.
  2) Direct Socket Peer IP Verification:
     Reads actual socket.remoteAddress directly from the connected TLS socket and asserts byte-for-byte
     equality with the pre-resolved pinned IP. Throws SOCKET_PEER_MISMATCH immediately if any
     discrepancy occurs, defeating DNS rebinding and proxy interception.
  3) TLS Certificate Authority Verification:
     Checks tlsSocket.authorized and certificate validity flags. Disallows self-signed, invalid, or
     expired certificates in production mode.
  4) Streaming Response Cap & AbortSignal Wiring:
     Streams response body with a strict 2 MiB (2097152 bytes) limit, aborting with BODY_TOO_LARGE
     if breached. Attaches abort listener to signal to cleanly destroy socket and cancel stream.
  5) Strict Test Isolation (isLiveExternalProof: false):
     Guarantees that test simulations or local loopbacks explicitly mark isLiveExternalProof: false.
     tlsVerified reflects HTTPS protocol status while external live authority remains fail-closed.

[WORKSTREAM B] Pure CSV Validation & Uniform Fail-Closed Demand Lineage
- Files: src/services/kh02/demand/googleTrendsCsvValidator.ts, src/services/kh02/demand/temporalDemandEngine.ts
- Vulnerabilities / Risks:
  Previously, verifyDemandObservationAgainstRawCsv called disk-reading persistence routines,
  risking file modification or timestamp alterations during read operations. In temporalDemandEngine,
  certain validation errors (e.g. KEYWORD_MISMATCH, REGION_MISMATCH, FILE_MISSING, SHA_MISMATCH)
  were not uniformly demoting observations to CACHED_UNVERIFIED, leaving open provenance gaps.
- Production Code Fixes:
  1) Pure Non-Mutating Parser (parseGoogleTrendsCsvBytes):
     Extracted parseGoogleTrendsCsvBytes as a pure functional parser with zero disk side effects.
     verifyDemandObservationAgainstRawCsv reads the file read-only and parses purely in memory,
     ensuring mtime and file SHA-256 remain bitwise identical before and after verification.
  2) Uniform Fail-Closed Lineage Demotion:
     Updated evaluateDemandSourceAuthority and hasVerifiableCsvOrProviderLineage to uniformly
     demote ALL row-level mismatch errors (KEYWORD_MISMATCH, REGION_MISMATCH, FILE_MISSING,
     SHA_MISMATCH, VALUE_MISMATCH, SOURCE_UNATTESTED) to CACHED_UNVERIFIED and lineageVerified: false.
  3) Source Isolation:
     Distinguishes GOOGLE_TRENDS_CSV from PROVIDER_API so CSV descriptors are validated by physical
     file existence and SHA-256 byte integrity without requiring live API request identifiers.

[WORKSTREAM C] Multi-Process SQLite WAL Concurrency & Atomic Imports
- Files: src/services/kh02/demand/demandObservationBatchImport.ts, src/app/api/v1/demand/import/route.ts, scripts/kh02/multiProcessImportWorker.ts
- Vulnerabilities / Risks:
  Sequential individual row inserts inside long-running interactive transactions held SQLite write locks
  for several seconds, causing concurrent OS worker processes to timeout with P1008 / SQLITE_BUSY.
- Production Code Fixes:
  1) SQLite WAL & Busy Timeout:
     Configured PRAGMA journal_mode=WAL and PRAGMA busy_timeout=15000 on active and template SQLite databases.
  2) High-Performance Atomic Batch Insertion:
     Replaced sequential row lookups inside transactions with pre-queried in-memory maps and single-operation
     createMany batch inserts. Reduced transaction hold time from ~4,000ms to ~10ms.
  3) Active Composite Unique Index:
     Enforces composite uniqueness on (productId, source, keyword, region, periodStart). Rejects concurrent
     duplicate insertions while maintaining all-or-nothing rollback on validation failure.
  4) Strict Provenance Mode:
     Added strictProvenance parameter to demand batch import. When true, rejects CSV imports lacking
     evidenceReference with 422 EVIDENCE_REFERENCE_REQUIRED, and rejects PROVIDER_API imports lacking
     verifiable provider receipts.
